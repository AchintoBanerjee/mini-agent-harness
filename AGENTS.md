# AGENTS.md

Mini agent harness: a small Java 21 agent loop (model stub -> tool call -> result -> model again), built for a take-home whose brief is `PROBLEM.md`.
`v1/` is the harness exactly as designed and built in the live round (tag `v1`) and is frozen: never edit it. All work is in `v2/`.

- Build and test: `cd v2 && mvn -q test` (94 tests, about 9 s with Maven's own start). Compile only: `mvn -q compile` (classes to `target/classes`, Jackson and sqlite-jdbc to `target/lib`).
- HTTP is the face. From `v2/`: `java -cp "target/classes:target/lib/*" harness.cli.Main serve [--port 8080]` (the JDK's `HttpServer`; it runs no loop) and `worker [--once] [--visibility-ms 2000] [--crash-after N] [--slow]` (takes turns off the queue, resumes a dead worker's turn from its saved spans, extends the lease on every span, acks last; `--crash-after N` exits 3 after its Nth row without acking; `--slow` gives every lookup 300 ms of simulated latency). The rest of the CLI is the developer's: `submit --agent <name> "question"` (a turn QUEUED plus its queue message, without HTTP), `eval [evals/golden.json]`, `replay <turnId> [fromSpan]`. On JDK 24+ put `--enable-native-access=ALL-UNNAMED` after `java`, or the SQLite driver's native load prints a warning.
- Endpoints: `GET /agents`, `GET /agents/{name}`, `GET /tools`, `POST /runs` (`{"agent","question"}` -> `202 {"turnId","jobId","conversationId","status":"QUEUED"}`; `{"conversationId","question"}` adds a turn to that conversation), `GET /turns/{id}` (alias `/runs/{id}`: the turn row with `answer`, `claimedBy`, `attempts`, and its spans), `GET /turns/{id}/events` (SSE: stored spans from `Last-Event-ID` or `?after=N`, the span number as the event id, then live, then `done`), `POST /evals` (the golden set scored in the server, `cases` and `lines`). No builder endpoint: agents and tools are files.
- Proof: `./demo.sh` from the repo root compiles v2, empties `harness.db` and runs the HTTP sections first, then durability, then the CLI that remains; `docs/demo-output.txt` is its saved output. The manual with each command's real output is `v2/README.md`; the high-level design is `docs/V2_HLD.md`; the queue, the lease and the dead worker are `docs/DURABILITY.md`.
- Design doc: `DESIGN.md` at the repo root. The live round's whiteboard is `docs/v1-whiteboard.png`.
- Data: agents are `v2/agents/*.json`, tools are `v2/tools/*.json` (`type` picks the adapter: `lookup`, `sleep`, `fail`), the golden set is `v2/evals/golden.json`. Turns live in `v2/harness.db` (SQLite, gitignored, created on first use): `conversation` (`id`, `agent`, `created_at`), `turn` (`id` = the job id, `conversation_id`, `question`, `answer`, `status` QUEUED · RUNNING · DONE · FAILED, `claimed_by`, `attempts`, `created_at`, `updated_at`), `span` (`turn_id`, `span`, `pass`, `kind`, `request`, `response`, `status`, `ms`, `attrs` JSON; span numbers run on through a conversation) and `queue` (`turn_id`, `visible_at`, `receives`: the message, the lease, the count). A file with the old `job`/`step` tables is refused: delete it. Tests use the in-memory store or a temp file, never that one.
- Rules: the model stays a stub (`RuleBasedLLM`, no network, no keys); the dependencies beyond JUnit are jackson-databind and sqlite-jdbc; the HTTP server is the JDK's `com.sun.net.httpserver.HttpServer`; the queue is a table in the same file with SQS's three calls (`RunQueue.receive/extend/ack`), no dead-letter path (out of scope for the POC), no Redis, no SQS client, no Temporal; plain Java, no frameworks, no preview APIs; the suite stays green and under about 10 s; names and strings stay honest (`TIMEOUT`, `SqliteRunStore`, "(latency simulated)").
- Git: commit from the repo root with a one-line message: `v2 step N: <what>` for the step builds, `v2 hld: <what>`, `v2 durability: <what>` and `v2 http: <what>` for the document builds; never push, never `git reset --hard`.
