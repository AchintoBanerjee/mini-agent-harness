# AGENTS.md

Mini agent harness: a small Java 21 agent loop (model stub -> tool call -> result -> model again), built for a take-home whose brief is `PROBLEM.md`.
`v1/` is the harness exactly as designed and built in the live round (tag `v1`) and is frozen: never edit it. All work is in `v2/`.

- Build and test: `cd v2 && mvn -q test` (126 tests, about 10 s with Maven's own start). Compile only: `mvn -q compile` (classes to `target/classes`, Jackson and sqlite-jdbc to `target/lib`).
- HTTP is the face. From `v2/`: `java -cp "target/classes:target/lib/*" harness.cli.Main serve [--port 8080]` (the JDK's `HttpServer`; it runs no loop) and `worker [--once] [--visibility-ms 2000] [--crash-after N] [--slow] [--api http://localhost:8080]` (takes turns off the queue, resumes a dead worker's turn from its saved spans, extends the lease on every span, acks last, pushes every event of a turn to the server named by `--api`, default `http://localhost:8080`; `--crash-after N` exits 3 after its Nth row without acking; `--slow` gives every lookup 300 ms and every token 40 ms of simulated latency). The rest of the CLI is the developer's: `submit --agent <name> "question"` (a turn QUEUED plus its queue message, without HTTP), `eval [evals/golden.json]`, `replay <turnId> [fromSpan]`. On JDK 24+ put `--enable-native-access=ALL-UNNAMED` after `java`, or the SQLite driver's native load prints a warning.
- Endpoints: `GET /agents`, `GET /agents/{name}`, `GET /tools`, `POST /runs` (`{"agent","question"}` -> `202 {"turnId","jobId","conversationId","status":"QUEUED"}`; `{"conversationId","question"}` adds a turn to that conversation), `GET /turns/{id}` (alias `/runs/{id}`: the turn row with `answer`, `claimedBy`, `attempts`, and its spans), `POST /turns/{id}/events` (the worker's push: `{"event":"step"|"token"|"done","data":{...}}`, appended to the run's stream the server holds -> `204`), `GET /turns/{id}/events` (SSE: the run's stream from `Last-Event-ID` or `?after=N`: each `step`, each `token`, the answer word by word, then `done`; the saved rows once, the span number as the id, only when the stream is gone), `POST /evals` (the golden set scored in the server, `cases` and `lines`). No builder endpoint: agents and tools are files.
- The stream and the stub: the loop is the producer of the run's stream (`RunListener`: `on` a step, `token`, `done` -> `HttpPush` -> `POST /turns/{id}/events` -> `RunStreams` in the API, a map per turn id, the stand-in for a Redis Stream); the store is the fallback, read only when the stream is gone. The stub chains from results after pass 1: pass 1 picks tools from the question, every later pass scans the turn's OK results for ids a tool knows and calls each (tool, id) that has no row yet, done when nothing new is named; so "What is the status of order ORD-1?" on `support` is five rows over three passes and the answer relays every result of the turn, one line each.
- Proof: `./demo.sh` from the repo root compiles v2, empties `harness.db` and runs the HTTP sections first, then durability, then the CLI that remains; `docs/demo-output.txt` is its saved output. The manual with each command's real output is `v2/README.md`. The pages: `docs/V2_HLD.md` (the design), `docs/V2_FEATURES.md` (what the loop already does, each with a run), `docs/DURABILITY.md` (the queue, the lease, the dead worker), `docs/SCALING.md`, `docs/PERFORMANCE.md`, `docs/SUBAGENTS.md`, `docs/EVAL.md`; `DESIGN.md` at the root is the spine that links them in build order. Every pasted output on a page comes verbatim from `docs/demo-output.txt`; when the demo changes, re-paste, never edit a block by hand.
- Diagrams: `docs/*.svg`, one house style (the classes at the top of any of them: beige boxes for the ordinary parts, blue for the section's subject, orange for the shared model, red for the cost paid today, cylinders for stores, the user on the left); no built/designed legends. Check a diagram by rendering it with headless Chrome at 1120 px wide. The live round's whiteboard is `docs/v1-whiteboard.png`.
- Data: agents are `v2/agents/*.json` (`maxModelCalls`, default 20, is the model calls one turn may spend, children included), tools are `v2/tools/*.json` (`type` picks the adapter: `lookup`, `sleep`, `fail`, `agent`; an `agent` tool names another agent, read from `agents/`, and its call runs that agent's loop inside the tool call: the child's spans land in the same turn with `parent` and `depth` in `attrs`, the parent's row is of kind `AGENT` and carries the child's answer; depth cap 2, one budget of model calls per turn), the golden set is `v2/evals/golden.json`. Turns live in `v2/harness.db` (SQLite, gitignored, created on first use): `conversation` (`id`, `agent`, `created_at`), `turn` (`id` = the job id, `conversation_id`, `question`, `answer`, `status` QUEUED · RUNNING · DONE · FAILED, `claimed_by`, `attempts`, `created_at`, `updated_at`), `span` (`turn_id`, `span`, `pass`, `kind` LLM · TOOL · AGENT · NOTE, `request`, `response`, `status`, `ms`, `attrs` JSON; span numbers run on through a conversation, a child loop's rows included) and `queue` (`turn_id`, `visible_at`, `receives`: the message, the lease, the count). A file with the old `job`/`step` tables is refused: delete it. Tests use the in-memory store or a temp file, never that one.
- Rules: the model stays a stub (`RuleBasedLLM`, no network, no keys); the dependencies beyond JUnit are jackson-databind and sqlite-jdbc; the HTTP server is the JDK's `com.sun.net.httpserver.HttpServer`; the queue is a table in the same file with SQS's three calls (`RunQueue.receive/extend/ack`), no dead-letter path (out of scope for the POC); the run's stream is a map in the API process (`RunStreams`) fed by the worker over HTTP (`HttpPush`), the stand-in for a Redis Stream, and the store is read for a client only when the stream is gone; no Redis, no SQS client, no Temporal; plain Java, no frameworks, no preview APIs; the suite stays green and under about 10 s; names and strings say what the thing is (`TIMEOUT`, `SqliteRunStore`, "(latency simulated)"); a stand-in for a production piece is named as one in its class comment, never presented as the design; comments in plain words, no "hack", no TODO, no internal product names, "my platform" when the owner's production system is meant.
- Git: commit from the repo root; the first line says what changed in plain words, `v2: ...` for code and `docs: ...` for pages; never push, never `git reset --hard`, never stash or revert edits you did not make (another agent or the owner may be mid-edit in files outside your task).
